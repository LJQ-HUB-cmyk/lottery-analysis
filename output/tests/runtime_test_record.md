## ⚠️ 发现的问题

### P0 — 功能阻塞

**无**

### P1 — 值得关注

1. **PLS 评分 Top-30 第30名显示号码不一致**
   - 现象：排名30 显示 `376(367)`，括号内为组选归一 367，但展示的原号码是 376
   - 输出数据确认：`pls_predict_26133.json` 中第30条 `号码":"376"`、`组选":"367"`，两者不一致（376≠367）
   - 文件：`scripts/scoring_engine.py`
   - 影响：展示层面错误，不影响实际的预测逻辑和后续对比
   - **建议**：检查 `_rank_and_display()` 或 `generate_predictions()` 中排序后号码与组选字段的映射关系

2. **PLS Top-1 直选命中率持续 0%（近7期）**
   - 数据：PLS default/conservative/diversity 三策略均为 0/7
   - 对比：D3 至少 1/7，随机策略回测100期也仅 3/100
   - **建议**：非 bug（彩票随机性），但推送文案可考虑弱化"直选"预期

3. **PLS 回测动态评分 ROI 不如随机策略**
   - 数据：
     - PLS 动态评分：ROI **-42.3%**（投入6000回报3462）
     - PLS 随机策略：ROI **+6.8%**（投入6000回报6407）
   - 对比 D3：动态评分 +70.2% 远超随机 +1.0%
   - **建议**：彩种间表现差异大，积累更多复盘数据后做权重调优

### P2 — 低优先级/已知

4. **PLS js-lottery 主源 fallback（仅解析10条）**
   - 现象：每次抓取日志显示 `js-lottery fallback: 解析到10条`，但最终 7607 条正确
   - 原因：主源页面结构可能变化，fallback 增量追加机制正常工作
   - 已记录在 `docs/待处理问题与后续计划.md`

5. **PLS 原始数据 7591 行日期列为空**
   - 现象：`feature_engine` 输出 `❌ 日期有7591个空值`，但 `--force` 跳过继续
   - 原因：历史种子数据（4001~4000+期）CSV中日期列为空，仅最新约16期有日期
   - 验证：`head -3 data/raw/pls_raw.csv` 有日期，`tail -20` 无日期
   - **建议**：不影响评分逻辑，无需修复

6. **sporttery 和 zhcw 备份源无成功记录**
   - 现象：`source_health` 中 `pls_sporttery 最后成功: 无记录`、`d3_zhcw 最后成功: 无记录`
   - 原因：主源正常，从未触发 fallback
   - **影响**：熔断器 fallback 链路未经过实战验证

7. **system Python 不通 PyPI 官方，需阿里云镜像**
   - `pip install` 对 `https://pypi.org` 超时（连接到超时）
   - `https://mirrors.aliyun.com/pypi/simple/` 正常（200，~200KB/s）
   - 已创建项目 venv 并安装完整依赖
   - **正式环境统一走 `.venv/bin/python`**（push 脚本已指向），不碰系统 Python
   - 新增依赖用 `uv + 阿里云镜像`，详见 `docs/HERMES_CONFIG.md` → "Python 环境约定"
